# 코드 읽기 안내서 (팀원용)

안내서는 AI 도구로 만든 코드를 팀이 직접 검증하라고 한다. 이 문서는 각자 맡은 부분을 **혼자 읽고 설명할 수 있게** 순서와 핵심 줄, 예상 질문을 정리한 것이다. 줄 번호는 이 문서를 쓴 시점 기준이다.

읽는 방법

1. 자기 담당 표의 파일을 위에서부터 순서대로 연다.
2. "확인할 것"을 직접 실행하거나 값을 바꿔 보면서 맞는지 본다.
3. "예상 질문"에 코드를 보지 않고 답할 수 있으면 끝이다.

전체 그림

```
게임(환경)  ──관측·보상──▶  알고리즘(PPO·DQN·SAC)  ──행동──▶  게임
   │                              │
   └── 학습 상대(self-play 풀, 봇)  └── 체크포인트 ──▶ 평가(봇 승률, 리그전 Elo) ──▶ 그래프·표
```

## A. 환경 담당

### 배구

| 순서 | 파일 | 볼 곳 | 핵심 |
|---|---|---|---|
| 1 | `volleyball/game.py` | 16~68줄 상수 | 코트 24×11, 60Hz 물리, 2프레임마다 행동(30Hz), 랠리 30초 제한 |
| 2 | 같은 파일 | 60~66줄 | 행동 번호 = 이동(3) × 위아래(3) × 타격(2) = 18개. 기본 행동은 타격 없이 6개 |
| 3 | 같은 파일 | `Game.step` (124줄) | 한 번 행동하면 2프레임 진행. 점수가 나면 승자, 30초를 넘으면 무승부(timeout) |
| 4 | 같은 파일 | `_move_player` (207줄) | 공중에서 타격 = 스파이크, 땅에서 이동+타격 = 다이빙, 다이빙 뒤 경직 |
| 5 | 같은 파일 | `observe` (340줄) | 관측 20개. **오른쪽 선수는 좌우를 뒤집어서** 항상 "나는 왼쪽"으로 보이게 한다 |
| 6 | `volleyball/vec_env.py` | `step` (29줄) | 경기 16개를 동시에 진행. 끝난 경기는 바로 다시 시작하고, 끝나기 직전 관측은 `final_obs`로 따로 준다 |
| 7 | `volleyball/bots.py` | `RuleBot._act_one` (40줄) | 공이 떨어질 위치를 예측해 이동하는 규칙 봇. 학습 없음 |

확인할 것

- `python -m tests.test_game`: 좌우 대칭, 같은 seed 재현, 다이빙 등 6개 검사
- `python play.py`로 직접 쳐 보고, 스파이크·다이빙이 설명대로 되는지

예상 질문

- **왜 오른쪽 선수의 관측을 뒤집나?** 정책 하나가 어느 코트에서든 똑같이 플레이하게 하려고. 안 뒤집으면 왼쪽용, 오른쪽용을 따로 배워야 하고 self-play에서 자기 자신과 붙일 수 없다.
- **보상은?** 득점 +1, 실점 -1뿐이다. 에피소드 = 한 점. 공을 넘기면 +0.1 주는 보조 보상은 E4에서 따로 실험했고 차이가 없었다.
- **30초 제한으로 끊긴 랠리는?** "끝"이 아니라 "중간에 끊김"(truncated)이다. 알고리즘은 이때 다음 상태 가치를 이어 붙인다(B, C 담당 부분 참고).

예상 질문

- **시간 초과를 왜 -1로 했나?** 0으로 두면 레이저 앞에 가만히 서 있는 게 가장 안전한 전략이 된다. 실제로 처음 설계에서 성공률이 0이었다.
- **매 스텝 -0.01은 왜?** 할인율 0.99에서 20초(200스텝) 뒤의 -1은 지금 거의 0으로 보인다. 버티는 비용을 바로 느끼게 하려고.
- **물리 엔진을 안 쓴 이유는?** 재현성(같은 seed → 같은 결과)과 속도(초당 약 1만 5천 스텝). 충돌은 캡슐과 레이저 선분의 최소 거리로 판정한다.

## B. PPO, self-play 담당

| 순서 | 파일 | 볼 곳 | 핵심 |
|---|---|---|---|
| 1 | `algos/ppo.py` | `act_train` (57줄) | 행동을 뽑으면서 관측, 행동, log 확률, 가치를 버퍼에 저장 |
| 2 | 같은 파일 | `observe` (68줄) | 시간 제한으로 끊긴 경우 보상에 γ·V(마지막 관측)을 더한다 (72~76줄) |
| 3 | 같은 파일 | 84~93줄 | **GAE**: δ = r + γV(s') − V(s), A = δ + γλA(다음) |
| 4 | 같은 파일 | `_update` (99줄) | **clipped objective** (124줄), 가치 손실, 엔트로피 보너스, 학습률 선형 감소 |
| 5 | `train.py` | `OpponentPool` (50줄) | 상대 = 과거 자신 60%(그중 절반은 최신), 쉬움 봇 20%, 무작위 봇 20% |
| 6 | 같은 파일 | 학습 루프 (172줄) | 10만 스텝마다 평가·스냅샷, 50만 스텝마다 체크포인트 |
| 7 | `laser/imitation.py` | `collect` (74줄), `train_student` (103줄) | 레이저: 단계별 PPO 선생님을 학생 정책 하나로 합치는 BC·DAgger |

확인할 것

- `python -m tests.check_algos`: CartPole에서 PPO가 학습되는지
- `python train.py --algo ppo --seed 0 --set total_steps=300000`: 로그에서 `approx_kl`, `clip_fraction`이 작게(대략 0.01, 0.1~0.2) 유지되는지

예상 질문

- **clip은 왜 하나?** 새 정책이 데이터를 모은 정책에서 너무 멀어지지 않게. 비율 r이 [0.8, 1.2] 밖이면 그 방향의 기울기를 끊는다.
- **advantage를 미니배치마다 정규화하는 이유는?** 보상 크기와 상관없이 업데이트 크기를 안정적으로 맞추려고.
- **같은 스텝에서 PPO가 약한 이유는?** 데이터를 4 epoch 쓰고 버린다. DQN·SAC는 50만 개 버퍼에서 여러 번 재사용한다. 대신 PPO는 계산이 가벼워서 같은 시간에는 4배 넘는 스텝을 쓸 수 있고, 그러면 1위가 된다(E5).
- **self-play에서 과거 버전을 섞는 이유는?** 최신 자신하고만 붙으면 서로의 약점만 파고들다 예전 전략을 잊는다(전략 순환). 과거 버전과 봇이 그걸 막는다. 가장 오래된 스냅샷 하나는 계속 남긴다(66줄).
- **DAgger가 BC보다 나은 이유는?** BC는 선생님이 간 상태만 배운다. 학생이 실수해서 처음 보는 상태로 가면 대처를 못 한다. DAgger는 학생이 직접 가 본 상태에서 선생님 답을 받아 배운다.

## C. DQN, SAC, 평가·분석 담당

| 순서 | 파일 | 볼 곳 | 핵심 |
|---|---|---|---|
| 1 | `algos/common.py` | `ReplayBuffer`, `FrozenPolicy` | 버퍼, 학습이 끝난 정책을 상대나 평가용으로 쓰는 래퍼 |
| 2 | `algos/dqn.py` | `observe` (60줄) | **terminated만 done으로 저장**한다. 시간 제한은 이어서 계산(bootstrap) |
| 3 | 같은 파일 | `_update` (77줄) | **Double DQN**: 다음 행동은 온라인망으로 고르고(81줄), 값은 타깃망으로(82줄). Huber 손실, 타깃망 soft update(τ=0.005) |
| 4 | 같은 파일 | `epsilon` (48줄) | 전체 학습의 앞 30% 동안 1.0 → 0.05 |
| 5 | `algos/sac.py` | `_update` (83줄) | 이산 SAC. 행동이 유한해서 기댓값을 **확률 가중합으로 정확히** 계산한다(94줄, 112줄) |
| 6 | 같은 파일 | 119~124줄 | alpha 자동 조절: 엔트로피가 목표(0.3 × log 행동 수)보다 낮으면 alpha를 키운다 |
| 7 | `volleyball/evaluate.py` | `play_points` | 두 선수가 n점을 겨룬 승률(무승부는 0.5) |
| 8 | `analysis/stats.py` | `mean_ci` (12줄) | 95% 신뢰구간. 표본 단위는 seed, t 분포(자유도 n−1) |
| 9 | 같은 파일 | `elo_from_wins` (27줄) | Bradley-Terry 모델을 MM 반복으로 풀고 400·log10으로 Elo 변환. 어려움 봇 = 1000 |
| 10 | `analysis/league.py` | `main` | 모든 모델과 봇을 서로 200점씩 붙인다 |

확인할 것

- `python -m tests.check_algos`: CartPole에서 DQN, SAC가 학습되는지
- `runs/results/league/winrate.csv`를 열어서, Elo 순서와 직접 대결 승률이 대체로 맞는지

예상 질문

- **Double DQN은 일반 DQN과 뭐가 다른가?** 일반 DQN은 타깃망 하나로 max를 고르고 그 값을 써서 Q를 과대평가한다. Double은 고르는 망(온라인)과 평가하는 망(타깃)을 나눈다.
- **이산 SAC가 연속 SAC와 다른 점은?** 연속에서는 행동을 샘플링해 기댓값을 추정한다. 이산에서는 모든 행동의 확률을 알기 때문에 Σ π(a|s)[Q − α log π]로 정확히 계산한다. 그래서 재매개화 트릭이 필요 없다.
- **신뢰구간 표본 단위가 왜 seed인가?** 같은 모델로 200점을 치는 건 같은 학습 결과를 여러 번 재는 것이다. 우리가 알고 싶은 건 "다시 학습해도 그 성능이 나오나"라서 독립 표본은 학습 seed다.
- **봇 승률과 Elo를 둘 다 쓰는 이유는?** 봇 승률은 고정 잣대지만 봇 약점 공략일 수 있다. 실제로 기본 행동 SAC는 봇에게 0.88인데 리그전에서는 DQN과 비슷했다(E2).
- **Elo 계산 전에 0.5를 더하는 이유는?** 한 번도 안 진 선수가 있으면 강함이 무한대로 발산한다. 작은 사전값으로 막는다.

## 공통으로 알아야 할 것

**terminated와 truncated의 차이.** 게임이 실제로 끝난 경우(득점, 레이저 접촉)는 다음 가치를 0으로 둔다. 시간 제한으로 끊긴 경우는 게임이 계속될 수 있었으므로 다음 가치를 이어 붙인다. 세 알고리즘 모두 이걸 구분한다(PPO 72줄, DQN 64~66줄, SAC 70~72줄). 구분하지 않으면 "30초가 되면 세상이 끝난다"고 잘못 배운다.

**재현 방법.** 모든 실행은 `config.json`에 설정, seed, 코드 버전(git 커밋), 라이브러리 버전을 남긴다. 같은 명령을 다시 실행하면 같은 결과가 나온다(같은 CPU 기준).

**실험 한 번에 무엇이 남나.**

```
runs/e1/ppo_seed0/
  config.json    설정과 환경 정보
  metrics.csv    10만 스텝마다 봇 승률, 플레이 통계, 손실값
  ckpt_*.pt      50만 스텝마다 정책
  model.pt       최종 정책
  log.txt        학습 로그
```

**팀이 직접 해 볼 최소 검증** (각 10분 이내)

```powershell
python -m tests.test_game
python -m tests.check_algos
python train.py --algo dqn --seed 0 --set total_steps=200000
python play.py --left runs/e5/ppo_12m_seed3/model.pt --right hard
```
