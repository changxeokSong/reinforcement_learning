# 프로젝트 계획: 알바트로스 배구

서강대 마스코트 알바트로스를 모티브로 한 2D 1:1 배구 게임을 직접 만들고, 같은 조건에서 학습한 PPO·DQN·SAC 에이전트끼리 리그전을 붙여 알고리즘별 강점과 약점을 비교한다.

과제 안내서 기준으로 이 주제는 "새로운 환경을 디자인하고 agent를 학습"하는 가장 권장되는 유형에 해당한다.

## 1. 연구 질문

| 번호 | 질문 | 보고서 항목 |
|---|---|---|
| RQ1 | 같은 학습 예산에서 PPO, DQN, SAC 중 어떤 알고리즘이 더 강한 배구 에이전트를 만드는가? | 여러 알고리즘 비교 |
| RQ2 | 스파이크·다이빙이 추가되어 행동 공간이 복잡해지면 알고리즘별 성능이 어떻게 달라지는가? | 다양한 설정 비교 |
| RQ3 | 하이퍼파라미터(PPO의 entropy 계수, 학습률)가 최종 실력에 얼마나 영향을 주는가? | hyperparameter 비교 |
| RQ4 | 알고리즘마다 플레이 스타일(스파이크 빈도, 수비 위치 등)이 다른가? | 결과 해석, 토의 |

모든 결과는 seed 5개로 반복하고 95% 신뢰구간과 함께 보고한다.

## 2. 환경 설계

### 게임 규칙

- 2D 코트 중앙에 네트가 있고, 양쪽에 알바트로스 캐릭터가 한 마리씩 있다.
- 공이 상대 코트 바닥에 닿으면 득점한다. 학습과 평가에서는 한 점이 한 에피소드다. 랠리가 30초를 넘으면 무승부로 끊는다. 사람이 할 때는 5점 내기다.
- 물리 엔진은 외부 라이브러리 없이 직접 구현한다(중력, 원형 충돌, 네트·벽 반사). 가볍고 결정적이며 빠르다.
- 물리는 60Hz로 계산하고, 에이전트는 2프레임마다 한 번 행동한다(frame skip 2).
- 학습 중에는 화면을 그리지 않는다. 사람 플레이와 영상 녹화 때만 pygame으로 그린다.

### 캐릭터

- 공식 로고나 공식 캐릭터 이미지는 쓰지 않고, 알바트로스를 단순한 도형으로 직접 그린다.
- 우리 팀은 서강 진홍색, 상대는 다른 색 알바트로스로 구분한다.
- 저장소가 공개되므로 학교 로고는 게임과 코드에 넣지 않는다.

### 행동 (Action)

방향키 3 × 위아래 3 × 타격 버튼 2 = **18개 이산 행동**.

| 입력 | 땅에 있을 때 | 공중에 있을 때 |
|---|---|---|
| 좌/우 | 이동 | 공중 이동(약하게) |
| 위 | 점프 | - |
| 타격 + 방향 | **다이빙**: 그 방향으로 몸을 던짐, 착지 후 잠깐 경직 | **스파이크**: 공이 가까우면 세게 내리꽂음. 위/아래/없음으로 각도 조절 |

- **기본 행동 공간**: 좌/우/정지 × 점프 여부 = 6개 (RQ2 비교용)
- **확장 행동 공간**: 위 18개
- 세 알고리즘 모두 같은 이산 행동 공간을 사용한다. SAC는 이산 행동용 버전을 쓴다.

### 상태 (State), 20차원

- 내 위치·속도, 공중 여부, 다이빙·경직 상태
- 상대 위치·속도, 공중 여부, 다이빙·경직 상태
- 공 위치·속도
- 공과 나의 상대 위치
- 모든 값은 [-1, 1] 근처로 정규화한다.
- **좌우 대칭 변환**: 오른쪽 선수의 관측은 좌우를 뒤집어서, 하나의 정책이 어느 쪽에서든 "내가 왼쪽"인 것처럼 플레이하게 한다. 이렇게 해야 self-play와 리그전이 가능하다.

### 보상 (Reward)

- 기본: 득점 +1, 실점 -1 (희소 보상)
- 보조 보상 실험(선택): 공을 쳐서 넘기면 +0.1
- 보조 보상은 reward hacking 위험이 있으므로 기본 실험은 희소 보상으로 하고, 보조 보상은 비교 실험으로만 사용한다.
- 알고리즘을 비교할 때는 보상 합계가 아니라 **승률**을 공통 지표로 쓴다.

### 상대 (Opponent)

- 랜덤 봇: 무작위 행동
- 규칙 기반 봇(쉬움, 어려움): 공 낙하 지점을 예측해 이동하고 타이밍에 맞춰 친다. 모든 에이전트의 실력을 재는 **고정 기준**이다.
- self-play: 10만 스텝마다 학습 중인 정책을 복사해 상대 풀(최대 20개)에 쌓는다. 절반은 최신 버전, 절반은 과거 버전 중 무작위로 붙는다. 최신 버전하고만 붙으면 전략이 빙빙 도는 현상이 생기기 때문이다.
- 학습 상대 비율: self-play 60%, 쉬움 봇 20%, 무작위 봇 20%. 에피소드가 끝날 때마다 상대를 다시 뽑는다.
- **어려움 봇은 학습에 쓰지 않는다.** 학습 때 본 적 없는 상대여야 실력을 재는 기준으로 쓸 수 있다.

## 3. 알고리즘

| 알고리즘 | 종류 | 핵심 구현 |
|---|---|---|
| PPO | on-policy, actor-critic | clipped objective, GAE, 병렬 환경 |
| DQN | off-policy, 가치 기반 | replay buffer, target network, Double DQN |
| SAC (이산) | off-policy, 최대 엔트로피 | 이산 행동용 actor, twin Q, 자동 온도 조절 |

- **세 알고리즘 모두 PyTorch로 직접 구현한다.** 안내서에 "인터넷 코드를 그대로 쓰면 표절"이라고 되어 있고, 알고리즘 구현이 30점 항목에 들어가기 때문이다. 외부 강화학습 라이브러리는 쓰지 않는다.
- 신경망 크기(MLP 256×2), 관측, 행동, 학습 스텝 수를 모든 알고리즘에서 동일하게 맞춘다.
- 각 구현은 CartPole-v1로 검증한다(`python -m tests.check_algos`). 세 알고리즘 모두 평균 리턴 195 이상에 도달하는 것을 확인했다.
- 세 알고리즘은 같은 학습 루프(`train.py`)를 쓴다. 환경, 상대, 평가 코드가 완전히 같다.

## 4. 실험 설계

### 실험 목록

| 실험 | 설정 | seed | 학습 횟수 |
|---|---|---|---|
| E1 알고리즘 비교 | PPO / DQN / SAC, 확장 행동 | 5 | 15 |
| E2 행동 공간 | 위 3개 × 기본 행동 | 5 | 15 |
| E3 하이퍼파라미터 | PPO entropy 계수 3종 (기본값 1개는 E1과 공유) | 5 | 10 |
| E4 보조 보상 (선택) | PPO, 보조 보상 있음 | 5 | 5 |

총 45회 학습한다. 1회 학습량은 300만 스텝이다. 이 PC(i7-13700KF)에서 1회에 PPO 약 7분, DQN 약 35분, SAC 약 85분이 걸린다. 12개를 동시에 돌리면 전체 실험이 하룻밤 안에 끝난다.

같은 스텝 수로 맞추면 off-policy 알고리즘(DQN, SAC)이 gradient 업데이트를 훨씬 많이 한다. 그래서 스텝 기준 비교와 실제 시간 기준 비교를 둘 다 보고한다.

예비 실험으로 하이퍼파라미터를 조정한 내역은 따로 기록하고, 본 실험 전에 설정을 고정한다.

### 평가 지표

1. **규칙 기반 봇 상대 승률**: 학습 중 일정 간격으로 200점씩 측정한다. 학습 곡선과 최종 실력을 보여준다.
2. **리그전**: 최종 에이전트 전부를 서로 100경기씩 붙인다.
   - 알고리즘 × 알고리즘 승률 히트맵
   - Elo(또는 Bradley-Terry) 점수 막대그래프
3. **플레이 스타일 통계**: 스파이크·다이빙 사용 빈도, 랠리 길이, 득점 유형
4. **학습 효율**: 같은 실력에 도달하기까지 걸린 스텝 수와 실제 시간

### 통계 처리

- 통계 단위는 **학습 seed**다. 같은 seed 안의 평가 경기들을 독립 표본으로 세지 않는다.
- seed 5개의 평균과 95% t 신뢰구간을 쓰고, seed별 값도 모두 표에 적는다.
- 학습 곡선은 평균 ± 신뢰구간 음영으로 그린다.
- 평가할 때는 정책을 고정하고(학습 중지), 탐욕적 행동과 확률적 행동 중 하나로 정해서 모든 알고리즘에 똑같이 적용한다.

## 5. 역할 분담

| 담당 | 구현 | 분석·보고서 |
|---|---|---|
| A: 환경 | 물리·규칙, 렌더링, 키보드 2인 플레이, 규칙 기반 봇, Gymnasium·self-play 래퍼 | 환경·상태·행동·보상 설계 슬라이드 |
| B: 알고리즘 1 | PPO, 병렬 환경 수집, self-play 상대 풀 | 알고리즘·하이퍼파라미터 슬라이드, RQ3 분석 |
| C: 알고리즘 2 + 평가 | DQN, 이산 SAC, 리그전, Elo, 신뢰구간·그래프 스크립트 | 실험 셋업·결과 슬라이드, RQ1·RQ2 분석 |

- 토의·결론은 셋이 함께 쓴다.
- AI가 작성한 코드는 담당자가 직접 읽고 설명할 수 있어야 한다. 안내서에 AI 코드 검증 의무가 있다.
- 각자 기능 브랜치에서 작업하고 PR로 서로 검토한다. 보고서의 기여도 표에 쓸 근거가 된다.

## 6. 일정 (4주)

| 주차 | 목표 | 완료 기준 |
|---|---|---|
| 1주 | 코드 검증, 게임 물리 확정 | 담당자가 자기 코드를 읽고 설명할 수 있음. 직접 플레이해 보고 물리값(속도, 스파이크 세기 등) 확정 |
| 2주 | 예비 실험 | seed 1~2개로 짧게 돌려 하이퍼파라미터 점검. 본 실험 설정 고정 |
| 3주 | 본 실험 | E1~E3 전부 실행, 리그전 실행, 결과 자동 집계 |
| 4주 | 분석·제출 | 그래프·표·영상, PPT 보고서, README, 모델 업로드 |

마감일은 강의 공지를 확인해 이 표에 날짜를 채운다. 3주차가 밀리면 E4부터 뺀다.

## 7. 저장소 구조

```
volleyball/      게임 물리·규칙, 벡터 환경, 봇, 평가, 렌더링 (A)
algos/           ppo.py (B), dqn.py, sac.py (C), common.py
train.py         세 알고리즘 공통 학습 루프, self-play 상대 풀 (B)
play.py          사람 플레이, 관전, GIF 녹화 (A)
experiments/     실험 일괄 실행
analysis/        리그전, Elo, 신뢰구간, 그래프 (C)
tests/           게임 검증, 알고리즘 검증
runs/            학습 결과 (Git 제외)
```

모든 학습 실행은 `runs/<실험>/<설정>_seed<n>/`에 설정값, 코드 커밋 해시, seed, 평가 기록, 체크포인트, 실행 시간을 자동으로 저장한다.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| self-play 학습이 불안정함 | 과거 버전 상대 풀 사용, 규칙 기반 봇으로 실력을 고정 측정. 불안정성 자체를 토의 소재로 사용 |
| 어떤 알고리즘이 전혀 학습되지 않음 | 규칙 기반 봇 쉬움 단계부터 시작하는 커리큘럼. 그래도 안 되면 원인 분석을 결과로 보고 |
| 직접 구현한 알고리즘에 버그 | CartPole 검증 통과. 담당자가 논문 수식과 코드를 한 줄씩 대조 |
| 시간 부족 | E4 → E3 순으로 축소. E1과 E2는 반드시 유지 |
| 게임 물리 튜닝에 시간이 너무 듦 | 1주차 말에 물리값 고정. 이후 수정하면 모든 실험을 다시 돌려야 함 |
